## 参考要点（2026-11-13 补齐）

> 这 6 题不用作答，读一遍对照即可。上面的「我的理解」留白保留着，等做完 P1-05 和 P1-08 再回来用自己的话写一遍 —— 那才是真正的验收。

**Q1 · RCC 是什么**

```c
#define RCC_BASE  (AHBPERIPH_BASE + 0x1000)   // 0x40021000
#define RCC       ((RCC_TypeDef *) RCC_BASE)
```

`RCC` 不是一个变量，是**被强转成结构体指针的固定地址**。`->` 只是「基地址 + 成员偏移」的语法糖。
`RCC_TypeDef` 里 `APB2ENR` 是第 7 个成员，每个 4 字节 → 偏移 6×4 = `0x18`。
所以 `RCC->APB2ENR` 实际访问 **0x40021018**。

**Q2 · 宏的意义**

`RCC_APB2ENR_IOPCEN` 展开约 `0x00000010`（bit 4）。
宏不是给编译器看的，是给人看的：`|= 0x10` 一个月后没人知道在干什么，`|= RCC_APB2ENR_IOPCEN` 一眼看出是开 GPIOC 时钟。

**Q3 · 为什么不能写 `=`**

APB2ENR 一个寄存器里塞了十几个外设的时钟开关（GPIOA bit2、GPIOC bit4、ADC1 bit9…）。
`=` 会把其他位全清零 → 别的外设当场断电。`|=` 只置 bit4，其余原样保留。
**铁律：改寄存器只改你要改的位。**

**Q4 · `~(0xFU << 20)`**

```
0xFU << 20 = 0x00F00000     // 4 个 1 落在 bit23~20
~          = 0xFF0FFFFF     // 那 4 位变 0，其余 28 位全 1
&=         → 只清那 4 位，其他位不动
```
PC13 的配置位正好在 CRH 的 bit23~20。
必须**先清再写**：若原来是 `0011`，直接 `|= 0x2` 得 `0011 | 0010 = 0011`，写入失败。

**Q5 · `^=` 翻转**

`x ^ 1` 在 x=0→1、x=1→0，每次取反，所以能一直闪。
`x | 1` 结果恒为 1，灯只亮不灭。

**Q6 · `1U` 的 U**

`U` = unsigned。C 里 `1` 默认有符号 int，`1 << 31` 移进符号位是**未定义行为**；`1U << 31` 明确按无符号算，得 `0x80000000`。
**写寄存器的常量一律带 U**，是习惯，不用每次想为什么。

## 收拢成一个模式

所有寄存器操作都是「读 → 改 → 写」：

| 写法 | 含义 |
|---|---|
| `reg \|= mask` | 把 mask 那些位置 1，其余不动 |
| `reg &= ~mask` | 把 mask 那些位清 0，其余不动 |
| `reg ^= mask` | 把 mask 那些位取反，其余不动 |
| `reg = value` | **危险**：其他位全被覆盖 |

嵌入式 90% 的寄存器代码，都是这三种写法的排列组合。
